# Production operations

- Prefer live updates when deploying TauCeti workers or fleet changes. Keep normal worker and CI admissions enabled; the operator prefers live repair and cleanup of any resulting problems over draining the system.
- Do not drain the fleet, pause admissions, or wait for the whole fleet to become idle as a routine deployment precaution. These changes confuse other agents monitoring production.
- Use a drain only when the user explicitly requests it or a concrete constraint makes a live update unsafe or impossible. Explain that specific constraint before changing admissions; a deployment command requiring a drain is a reason to find a live update path, not automatic authorization to drain.
- After a live update, verify the running revisions, useful completions, and any interrupted or stranded work, and repair problems within the authorized scope.
- The queue controller, repair workers and monitoring units on tauchonki2 run origin/main HEAD, each install from its own release directory under `~/TauCetiQueue-releases` (made from the shared clone `~/TauCetiQueue`), installed by `services/queue/install.sh`, `install-repair.sh` and `install-monitoring.sh` with no arguments; `services/queue/release.sh status` shows what each unit runs. Never use systemd drop-ins for queue units; the installers refuse to run while one exists. Running another revision (`--revision`/`--release`/`--checkout`) requires explicit permission from a human operator, and whoever does it must rerun the installer with no arguments as soon as their change lands on main (docs/queue/operations.md, "Install and update").
- Restart the queue controller only at a safe point: run `services/queue/install.sh` as usual, since it waits by default (seconds, normally) until no promotion, CI dispatch or controller replay is in flight, and `services/queue/release.sh safepoint` shows what is in flight. This times the restart; it is not a drain, and admissions stay on. Do not pass `--no-safepoint`, or restart `tauceti-queue.service` with `systemctl` directly, unless the controller is wedged in a busy state; exit 3 means no safe point came within `--safepoint-timeout`, so rerun later (docs/queue/operations.md, "Install and update", "Safe point").
- Deploy only code merged to origin/main. Never hot-install worker, audit or fleet components from an unmerged branch or a local edit: production must never run code main lacks, or a later install from main silently reverts it. If a fix is urgent, ask the user to merge it first.
- Known issue, do not report: about 750 TauCeti Actions runs (mostly created 2026-11-11), and a few in TauCetiWorker and TauCetiFleet, report `queued` forever with no jobs ("GitHub zombie runs"). They are harmless; cancel and force-cancel return HTTP 409 and delete returns HTTP 403. We never file GitHub support requests about them (Kim, 2026-11-20). Reporting excludes them and jobs queued over 24 hours; `tauceti-fleet status` text omits them. Do not report, investigate, cancel or delete them; docs/queue/github-zombie-runs.md has the policy and the record.
- Known, do not report: the queue repair workers (`tauceti-queue-repair`, `@2`, `@3` on tauchonki2) are meant to run on the API-billed `api` provider. The Claude and Codex subscription providers rank above it in the chain only for testing and are optional (Kim, 2026-11-25). While they are logged out or expired the repair logs show skip lines such as `provider claude skipped: no claude accessToken` and `provider codex skipped: codex token expired; refresh left to the operator` (or another missing or expired credential reason); that is expected. Do not report, file, investigate or log in again over these lines unless Kim asks; docs/queue/repair-task.md, "Providers", has the policy.
