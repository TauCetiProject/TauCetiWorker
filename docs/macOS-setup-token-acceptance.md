# Native macOS acceptance: Claude agent-file routing

Run this packet on the operator's Mac against the immutable Worker and Review revisions supplied by the coordinator. Linux platform stubs do not satisfy its native checks.

## Inputs and isolation

The coordinating agent supplies these immutable inputs alongside this packet:

- Worker repository URL and exact tested commit, including #676 and #682.
- Review repository URL and exact tested commit. Resolve the default-branch runtime Worker will actually select; an old installed distribution is not sufficient. Record both the configured and resolved revisions.
- The versioned acceptance fixture/commands corresponding to those revisions. Fixture code must be readable before execution and print only booleans, exit status, paths relative to the acceptance root and nonsecret version information.
- A fresh dedicated agent config directory and an operator-provided valid setup-token credential file for account **agent-A**. A replacement setup-token file for that same account is needed for case 3. Tokens are read from files, never shell arguments, command history or report text.
- A separate operator-owned usage-login file for the **same account**, obtained for this installation rather than copied from an independently refreshing host. Do not enable automatic renewal in these acceptance checks. Record whether the account match is verified or merely asserted.
- One operator-approved entitled Claude model and a maximum of **two** minimal model calls: one direct file-route call and one final Review subprocess call. Everything else is offline or authentication/usage inspection. If the first authentication fails, stop before the paid calls and report the error category.

Create a new mode-0700 acceptance directory using `mktemp -d` under the Mac user's home, with private `agent-source/`, `usage-source/`, `worker-state/`, `runtime/`, `activity/`, `review-homes/`, `empty-repository/` and `results/` directories. Set the fixture's Worker data/state/runtime/activity paths to these locations. Use a fresh worker ID such as `mac-file-<UTC timestamp>`. Do not reuse an existing slot or its seeded home. Keep the real login `HOME`, `USER` and `LOGNAME` intact where macOS Worker requires them; override the supported Worker state paths instead of impersonating another login with HOME.

Copy only the specifically supplied setup-token into the private agent-source `.credentials.json`, mode 0600. Do not copy the user's full `.claude`, settings, skills, project files, or Keychain contents. Keep the usage source separate. The fixture must avoid refresh-token rotation and must not attach raw credential files or model JSON to the result.

Record `sw_vers`, machine architecture, Python version, Worker commit, resolved Review commit, `claude --version`, and the `claude` executable's SHA-256. Record only a redacted authentication label, never email, account ID or tokens.

## Eight acceptance cases

| Case | Procedure | Required evidence and result |
| --- | --- | --- |
| **1. Native baseline and configured-file authentication** | With the dedicated config directory, usage file configured, no `ANTHROPIC_API_KEY`, and no exported `CLAUDE_CODE_OAUTH_TOKEN`, run `claude auth status --json` in a subprocess whose environment exactly matches the agent's final host route. Parse output locally; retain only logged-in boolean, auth method and whether the expected account matches. Once authentication is confirmed, perform the one operator-approved direct `claude -p` probe with no tools and a fixed short reply instruction. | Actual macOS CLI exits successfully with the configured agent account. No login/Keychain unlock prompt appears. The direct model probe returns the short expected reply. In the same fresh directory, move only the acceptance credential copy aside and repeat `claude auth status`: it must become unauthenticated despite the untouched operator login, then recover when that copy is restored. This positive/negative pair establishes native file use rather than merely observing a successful account. CLI version, exit status and normalized account-match boolean are recorded. Successful usage inspection alone does not prove this case. |
| **2. Worker isolation, usage separation and final environment** | Call the final Worker's actual isolation/mirroring and credential-admission helpers using the fresh nondefault worker ID. Inspect only booleans: worker source marker resolves to agent-source, isolated agent credential equals the supplied setup-token in memory, usage source resolves to usage-source, and neither source file was changed. The fixture's actual child process reports environment variable names only. | The agent gets its file route; the usage login is neither copied to the agent config nor present in the child's environment. No raw token appears in argv or logs. The Mac login HOME remains the operator HOME where required; Worker-specific state stays under the acceptance root. For the final Review child, HOME/config must instead be private as in case 7. |
| **3. Replace the agent token in the same running-worker source** | Atomically replace only acceptance `agent-source/.credentials.json` with the operator-provided second setup-token for agent-A. Use the same fresh worker ID and same source path, invoke the actual mirror helper, and inspect the native CLI's `auth status` in its final environment again. Compare credentials in memory and emit only `replacement_reached_worker=true/false`. | Worker copy changes to token 2; source marker and usage file remain unchanged. The native CLI remains authenticated as agent-A. This must not rely on making a new worker ID after replacement. No second paid direct probe is required. |
| **4. Directory-specific Keychain shadow and unknown-result handling** | Query the final Worker's metadata-only shadow diagnostic for **each actual config path used**: agent-source, isolated Worker config and the final Review private config. Record found/absent/unknown plus CLI version and the service-derivation version. Verify the current CLI's actual service lookup using a bounded fixture-only PATH wrapper around `security` that logs only the subcommand and `-s` service name and delegates read commands unchanged to `/usr/bin/security`; never log password output/complete argv. If the native CLI uses in-process Keychain APIs and no lookup is observable, source inspection or another non-destructive version-specific proof is needed; otherwise mark service derivation unverified. After verifying a unique service belongs only to a new disposable config directory, an optional positive test may add one **new synthetic placeholder** item for that exact test service, require the Worker's preflight to block, then remove only that newly created item. Precheck absence first and abort if any item already exists; never touch an existing item, operator credentials or search-list configuration. | A found or unknown shadow blocks the claimed file-route acceptance, or is explicitly unsupported rather than silently promising file precedence. A not-found result is conclusive only after verifying service derivation for the actual native CLI version. Native valid-file/absent-file controls from case 1 remain mandatory. If no safe native positive test is run, mark it NOT RUN and label simulated found/unknown fixture tests separately. A new scoped synthetic item is allowed only for an already-proved unique disposable service, never as a guessed probe against a real credential service. |
| **5. Missing/expired agent file: status and work agree** | Use only acceptance copies. Temporarily rename the agent-source file, then use a synthetic already-expired nonrenewable agent token in that path. Keep the valid separate usage file available. Invoke the actual final credential-admission logic for status/dashboard and work routes, with network/model boundaries trapped by the fixture. Also test an exported synthetic `CLAUDE_CODE_OAUTH_TOKEN` against the **file** reviewer route. Restore the acceptance source afterward. | Missing/expired configured agent file blocks file-route work before model execution and before an unnecessary usage request. Status/dashboard does not advertise that route as available. An environment token must not disguise a missing file for a child that receives only the file. Actual token expiry is checked locally; synthetic controls make no live authentication call. Record model-call count 0 and usage-request count 0 for these refusals. |
| **6. Usage-only identity and nonrenewal** | With valid token 2 restored, invoke the actual quota reader once against the dedicated usage login, without `--auto-refresh` or other renewal ownership. Record endpoint status category and a redacted window summary. Run the fixture's offline same-account mismatch/missing-usage-file controls. Hash the usage file locally before/after but publish only the unchanged boolean. | Agent authentication is never taken from the usage file. A missing/rejected usage source is reported separately from missing agent authentication; account mismatch is refused if provable. The original usage source is unchanged, no refresh token is spent, and an unverifiable same-account relationship is recorded as an assertion rather than a verified identity. A quota outage is not treated as proof that agent auth succeeded. |
| **7. Actual resolved Review final subprocess** | Import `reviewer_env` from the **resolved final Review revision**, not a test double. Prepare a Claude subscription reviewer from the Worker's configured agent file. Before calling the provider, verify private HOME/private CLAUDE_CONFIG_DIR, mode-0600 agent copy, no usage credential/token variable/GitHub credential, and no copied settings. Run native `claude auth status` with that exact returned environment. If it matches agent-A, execute the second and final approved minimal model call through the actual Review `run_claude` adapter, using an empty local repository and no PR posting. Clean the private Review home using its actual cleanup helper. | The final provider subprocess really authenticates and replies under the configured file route. A Worker helper or parent environment passing alone is insufficient. The reviewer never falls back to operator HOME for an explicitly configured file. Usage credentials, operator settings and GitHub tokens remain absent. Cleanup removes only the created reviewer home. Record exact Review SHA and whether its final default-branch/runtime selection matches the tested revision. |
| **8. Unset controls and supported-route boundary** | In a short-lived subprocess only, unset the separate usage-login variable and CLAUDE_CONFIG_DIR and run read-only native `claude auth status` using the operator's existing normal login. Do not sign in, sign out, unlock or refresh it. Compare the result with a pre-test read-only baseline. Run the final offline control modules for `mirror_creds_macos`, `claude_keychain`, and agent seeding on the native platform. | Existing unset behavior is preserved, even if the operator's baseline is not authenticated; the test must match that baseline rather than create a login. The acceptance packet does not claim Bubble code-writing support. Bubble credential staging may be checked offline with owned files, but a real container launch is a separate prerequisite/test and is not simulated as a native success. |

The direct minimal probe should use the installed CLI's verified flags, for example `claude -p --model MODEL --permission-mode dontAsk --tools '' --output-format json 'Reply only ROUTE_OK'` from the empty repository. The fixture must launch this as a structured subprocess argument list and parse the response privately. Do not put a credential in that argument list. The Review adapter may use its existing read-only tool set; the tiny fixture prompt must not request tools, code edits, external data or a review publication. `--max-budget-usd` is API-specific and is not a subscription spending cap; the limit here is the explicit two-call budget.

## Result artifact and retrieval

Write `results/result.json` and `results/summary.md` containing:

- Environment/version/commit data above, UTC start/end and the acceptance fixture version.
- One row per case: PASS, FAIL, BLOCKED or NOT RUN; observed exit status; native versus simulated; authentication label/account-match boolean; no token, refresh token, credential digest, email or full provider response.
- The two permitted model-call slots and whether each was used; network/renewal assertions and any unexpected prompt.
- Source files unchanged/restored booleans, reviewer-home cleanup status, and exact remaining limitations (especially native positive shadow or unsupported service derivation).

Retain raw outputs only locally inside mode-0700 results if needed for diagnosis, after reviewing them for personal data; do not upload them by default. Preserve the acceptance directory for the operator rather than recursively deleting a guessed path. Never remove an existing Keychain item, existing credential source or preexisting worker state. The only permitted Keychain cleanup is the exact newly created synthetic item recorded by case 4, after absence was established before creation.

Preferred handoff is the Mac agent returning the redacted artifact through its existing agent channel. If remote retrieval is needed, the coordinator can fetch a user-designated result file over the existing SSH connection or ask the Mac agent to paste the redacted JSON in an explicitly authorized comment on Worker #682. A GitHub comment should identify all tested SHAs and link the versioned packet; do not create a new issue just to hold a result unless the user requests one. The coordinating agent supplies the result destination alongside the exact revisions. The Linux coordinating agent must retrieve and inspect the result before marking native acceptance complete; existence of a link or a simulated PASS is insufficient.

## Native CLI compatibility

Record and verify the installed CLI's actual service lookup before relying on the Worker's
metadata check. A Linux native executable and platform stubs do not establish macOS Keychain
behavior. If the service convention or credential precedence differs from the candidate,
report the concrete behavior and correct the candidate before rerunning acceptance.
