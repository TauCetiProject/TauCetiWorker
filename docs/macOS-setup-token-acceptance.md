# Native macOS acceptance: Claude agent-file routing

Run this packet on the operator's Mac against the immutable Worker and Review revisions supplied by the coordinator. Linux platform stubs do not satisfy its native checks.

## Inputs and isolation

The coordinating agent supplies these immutable inputs alongside this packet:

- Worker repository URL and exact tested commit, including #676 and #682.
- Review repository URL and exact tested commit. Resolve the default-branch runtime Worker will actually select; an old installed distribution is not sufficient. Record both the configured and resolved revisions.
- The versioned acceptance fixture/commands corresponding to those revisions. Fixture code must be readable before execution and print only booleans, exit status, paths relative to the acceptance root and nonsecret version information.
- A fresh dedicated agent config directory and an operator-provided valid setup-token credential file for account **agent-A**. A replacement setup-token file for that same account is needed for case 3. Tokens are read from files, never shell arguments, command history or report text.
- A separate operator-owned usage-login file for the **same account**, obtained for this installation rather than copied from an independently refreshing host. Do not enable automatic renewal in these acceptance checks. Record whether the account match is verified or merely asserted.
- One operator-approved entitled Claude model and a maximum of **two** minimal model calls: one direct file-route call and one final Review subprocess call. Everything else is offline or source/usage inspection. `claude auth status` reads local state and can report logged in for a garbage token: it is not an authentication test. If the first approved model call fails, stop before the second and report only the error category.

Create a new mode-0700 acceptance directory using `mktemp -d` under the Mac user's home, with private `agent-source/`, `usage-source/`, `worker-state/`, `runtime/`, `activity/`, `review-homes/`, `empty-repository/` and `results/` directories. Set the fixture's Worker data/state/runtime/activity paths to these locations. Use a fresh worker ID such as `mac-file-<UTC timestamp>`. Do not reuse an existing slot or its seeded home. Keep the real login `HOME`, `USER` and `LOGNAME` intact where macOS Worker requires them; override the supported Worker state paths instead of impersonating another login with HOME. A fixture without an active project must inject `_worker_iso_home` using its existing `_base` parameter to keep the isolated home inside the acceptance root; there is no general environment override for the macOS isolated-home base. Resolve fixture temporary-directory roots before comparing them to normalized production paths (`/var` and `/tmp` can alias `/private/var` and `/private/tmp`).

Copy only the specifically supplied setup-token into the private agent-source `.credentials.json`, mode 0600. Do not copy the user's full `.claude`, settings, skills, project files, or Keychain contents. Keep the usage source separate. The fixture must avoid refresh-token rotation and must not attach raw credential files or model JSON to the result.

Record `sw_vers`, machine architecture, Python version, Worker commit, resolved Review commit, `claude --version`, and the `claude` executable's SHA-256. Record only a redacted authentication label, never email, account ID or tokens. Before testing, record only the presence/absence/unknown boolean for the operator's default Claude Keychain service using metadata without `-w`; the absent-file control cannot prove independence from an existing default login if no such login exists.

The direct minimal probe should use the installed CLI's verified flags, for example `claude -p --model MODEL --permission-mode dontAsk --tools '' --output-format json 'Reply only ROUTE_OK'` from the empty repository. The fixture must launch this as a structured subprocess argument list and parse the response privately. Do not put a credential in that argument list. The Review adapter may use its existing read-only tool set; the tiny fixture prompt must not request tools, code edits, external data or a review publication. `--max-budget-usd` is API-specific and is not a subscription spending cap; the limit here is the explicit two-call budget.

## Result artifact and retrieval

Write `results/result.json` and `results/summary.md` containing:

- Environment/version/commit data above, UTC start/end and the acceptance fixture version.
- One row per case: PASS, FAIL, BLOCKED or NOT RUN; observed exit status; native versus simulated; authentication label/account-match boolean; no token, refresh token, credential digest, email or full provider response.
- The two permitted model-call slots and whether each was used; network/renewal assertions and any unexpected prompt.
- Source files unchanged/restored booleans, reviewer-home cleanup status, and exact remaining limitations (especially native positive shadow or unsupported service derivation).

Retain raw outputs only locally inside mode-0700 results if needed for diagnosis, after reviewing them for personal data; do not upload them by default. Preserve the acceptance directory for the operator rather than recursively deleting a guessed path. Never remove an existing Keychain item, existing credential source or preexisting worker state. The only permitted Keychain cleanup is the exact newly created synthetic item recorded by case 4, after absence was established before creation.

Preferred handoff is the Mac agent returning the redacted artifact through its existing agent channel. If remote retrieval is needed, the coordinator can fetch a user-designated result file over the existing SSH connection or ask the Mac agent to paste the redacted JSON in an explicitly authorized comment on Worker #682. A GitHub comment should identify all tested SHAs and link the versioned packet; do not create a new issue just to hold a result unless the user requests one. The coordinating agent supplies the result destination alongside the exact revisions. The Linux coordinating agent must retrieve and inspect the result before marking native acceptance complete; existence of a link or a simulated PASS is insufficient.
