# Fork publication recovery

Worker retains fork intents until a complete authenticated read verifies an owned, writable fork with the requested upstream's immutable ID in its ancestry. A fork may have any name. A read error, partial response, missing permission, private visibility, changed identity, truncated ancestry, or conflicting same-name repository preserves the intent. Reads use the shared credential cache and quota transport.

After two complete public absence observations separated by five minutes, the outbox may replay creation once. This limit survives restart. Legacy personal-fork intents require a pinned account matching the authenticated viewer and are migrated with actor/upstream evidence. Replays use `gh repo fork OWNER/REPO --clone=false`, as fixed independently by TauCetiProgress #8. Verified fork receipts remain in `.complete` files. Unknown fork options remain retained for inspection.

Prepared report receipts bind the original account to hashes of the plan and both prose bodies. Publication resumes `apply` with those files and the original tool version before planning or model work. A five-minute publication backoff replaces the prose-generation error breaker for this path. Legacy reports can be adopted only with matching retained fork evidence from the same roadmap checkout. Completed receipt hashes prevent re-adopting a report. Existing deterministic branch and PR checks prevent duplicate publication. Corrupt receipts and account changes preserve files for inspection and allow unrelated PR work.

Deployment requires the companion Progress release (including R0) to be pinned by Worker. After an idle-boundary upgrade, ordinary rounds reconcile naturally retained intents and resume the saved reports. Inspect private intents using `python -m tauceti_worker.github_outbox list`; do not bulk-delete intents or force retries. No synthetic repository creation is needed. Production deployment/pin refreshes belong to the rollout coordinator for #302; record natural recovery separately from implementation and release receipts.

Rollback preserves the outbox, `.complete` fork evidence, `progress/work/publication*.json`, plan, prose, and local branches. Stop progress selection before rolling back to a version that lacks receipt-aware resume; that older version would delete saved prose on its next new report attempt. Never mark an uncertain write rejected to make rollback replay it.
