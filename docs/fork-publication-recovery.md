# Fork publication recovery

Worker retains fork intents until a complete authenticated read verifies an owned, writable fork with the requested upstream's immutable ID in its ancestry. A fork may have any name. A read error, partial response, missing permission, absence under private visibility, changed identity, truncated ancestry, or conflicting same-name repository preserves the intent. Reads use the shared credential cache and quota transport.

After two complete public absence observations separated by five minutes, the outbox may replay creation once. This limit survives restart. Legacy personal-fork intents require a pinned account matching the authenticated viewer and are migrated with actor/upstream evidence. Replays use `gh repo fork OWNER/REPO --clone=false`, as fixed independently by TauCetiProgress #8. Verified fork receipts remain in `.complete` files. Unknown fork options remain retained for inspection.

Prepared report receipts bind the original account to hashes of the plan and both prose bodies. Publication resumes `apply` with those files and the original tool-version label before planning or model work (the executable uses the current fixed pin). A five-minute publication backoff replaces the prose-generation error breaker for this path. Legacy reports require same-worker fork intent evidence for the original actor/upstream and a local deterministic report branch whose exact window matches the saved plan. Old proxies recorded Worker cwd, so cwd and prose timestamps are not used as identity evidence. Completed receipt hashes prevent re-adopting a report. Existing deterministic branch and PR checks prevent duplicate publication. Corrupt receipts and account changes preserve files for inspection and allow unrelated PR work. Six publication attempts, or a deterministic stale/invalid-branch result (exit 78), park the plan, bodies, facts and receipt under `progress/retained/` before releasing the active receipt. Local branches and GitHub intents remain intact. Parked bundles can be inspected and applied with the original actor and version label after the cause is repaired; do not regenerate their prose. Exhausted fork intents back off for an hour between discovery reads.

Deployment requires the companion Progress release (including R0) to be pinned by Worker. After an idle-boundary upgrade, ordinary rounds reconcile naturally retained intents and resume the saved reports. Inspect private intents using `python -m tauceti_worker.github_outbox list`; do not bulk-delete intents or force retries. No synthetic repository creation is needed. Production deployment/pin refreshes belong to the rollout coordinator for #302; record natural recovery separately from implementation and release receipts.

Rollback preserves the outbox, `.complete` fork evidence, `progress/work/publication*.json`, `progress/retained/`, plan, prose, and local branches. Stop progress selection before rolling back to a version that lacks receipt-aware resume; that older version would delete saved prose on its next new report attempt. Never mark an uncertain write rejected to make rollback replay it.

Standalone Progress journals uncertain mutations privately. Under Worker, the installed proxy owns the sole mutation journal; local quota waits do not consume mutation replay allowances. Authoritative pre-request or quota rejections refund the Worker fork replay allowance. A compound close-plus-comment is never replayed merely because the PR remains open: the comment may already have been posted.
